Space metadata

Spaces say what the data means, not just its shape.

Every leaf can carry a small shared vocabulary: kind, units, frame, rotation, names, source, fps. Tools read it, so you stop passing per-key configuration around.

BoxSpace(backend, 0, 255, np.uint8, shape=(480, 640, 3),
         metadata={"kind": "image", "format": "rgb",
                   "layout": "HWC", "source": "wrist_cam",
                   "fps": 15})

Quick start

From a space to a running loop.

  1. Describe your dataBuild the observation and action spaces once.
  2. Wrap the sourceA simulator, robot or dataset adaptor exposes those spaces.
  3. Write everything else oncePolicies, buffers and remote serving read the spaces, not the source.
import numpy as np
from unienv_interface.backends.numpy import NumpyComputeBackend as B
from unienv_interface.space.spaces import BoxSpace, DictSpace
from unienv_data.replay_buffer import ReplayBuffer
from unienv_data.storages.parquet import ParquetStorage

space = DictSpace(B, {
    "obs":    BoxSpace(B, 0.0, 1.0, np.float32, shape=(4,)),
    "action": BoxSpace(B, -1.0, 1.0, np.float32, shape=(2,)),
})

buffer = ReplayBuffer.create(
    ParquetStorage, space,
    cache_path="cache/demo", capacity=10_000,
)
import numpy as np
from unienv_interface.backends.numpy import NumpyComputeBackend as B
from unienv_interface.space import BoxSpace
from unienv_interface.policy import Policy

class RandomPolicy(Policy):
    # the policy declares what it reads and what it outputs
    backend, device = B, None
    observation_space = BoxSpace(B, -np.pi, np.pi, np.float32, shape=(7,))
    action_space = BoxSpace(B, -1.0, 1.0, np.float32, shape=(7,))

    def __init__(self, seed=0):
        self.rng = B.random.random_number_generator(seed)

    # state comes from reset / observe_transition; a random policy keeps none
    def reset(self, context, observation, **kwargs): pass
    def observe_transition(self, action_taken, new_observation): pass

    def get_action(self, **kwargs):
        return self.sample_action()

policy = RandomPolicy()  # or one served remotely: client.policy("pi")

policy.reset(context, obs)
for _ in range(100):
    action = policy.get_action()
    obs, reward, terminated, truncated, info = env.step(action)
    policy.observe_transition(action, obs)

Performance

Zero-copy where data moves, tuned where it is stored.

Tensors cross frameworks and processes without being copied, and the storages are benchmarked on robot-sized data: camera frames, proprioception, long episodes.

Zero-copy across backends

space.data_to(x, backend=...) hands arrays between frameworks through DLPack: the result is a view of the same memory.

0 copiesNumPy ↔ PyTorch on the CPU, PyTorch ↔ JAX on the GPU

Shared-memory vectorized envs

AsyncVecEnv workers write observations into one shared buffer that the parent reads in place; CUDA envs share GPU memory over CUDA IPC.

20–35×more steps/s than through pipes (PyTorch CPU, 8 workers)

Storage tuned on robot data

HDF5, Parquet, video and LeRobot storages are profiled on camera frames and long episodes, and read only the rows and columns a batch needs.

~20×faster Parquet dumps with array_encoding="binary"

Speedups are against UniEnv's previous implementation of the same feature, measured on one workstation; absolute times depend on the machine. Reproduce them with the scripts in benchmarks/.
